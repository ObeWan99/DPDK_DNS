# Виртуальное адресное пространство, программа и ОЗУ

## 1. Что такое виртуальное адресное пространство?
- Логическое пространство адресов, которое предоставляется программе.
- Позволяет программе работать с памятью, не зная о её реальном физическом расположении.
- Размер зависит от архитектуры процессора и операционной системы:
  - На 32-битной системе — до 4 ГБ.
  - На 64-битной системе — теоретически до 16 эксабайт.

## 2. Как размещается программа?
- При запуске программы операционная система:
  - Создаёт для неё виртуальное адресное пространство.
  - Загружает код и данные программы в ОЗУ или в файл подкачки.
- Программа обращается к данным через виртуальные адреса.

### Пример структуры виртуального адресного пространства:
| Адрес      | Содержимое                   |
|------------|------------------------------|
| 0xF0000000 | Ядро ОС                      |
| 0x80000000 | Стек                         |
| 0x40000000 | Куча                         |
| 0x00000000 | Код и статические данные     |

## 3. Роль MMU (Memory Management Unit)
- Выполняет преобразование виртуальных адресов в физические.
- Сопоставление виртуальных и физических адресов хранится в таблицах страниц.
- Если данных нет в ОЗУ:
  - Возникает **ошибка страницы**.
  - Операционная система загружает нужные данные из файла подкачки.

## 4. Связь виртуального адресного пространства, программы и ОЗУ
1. **Программа использует виртуальные адреса** для работы с памятью.
2. **MMU преобразует виртуальные адреса в физические**.
3. **Операционная система управляет ОЗУ**:
   - Активные данные хранятся в оперативной памяти.
   - Неактивные данные выгружаются в файл подкачки.
4. **Физическая память содержит только активные страницы.**
   - ОЗУ используется как кэш для наиболее востребованных данных.

## 5. Пример работы
- Программа обращается к адресу `0x40001234` (виртуальный адрес).
- MMU преобразует его в физический адрес, например, `0x12345678`.
- Если данные в ОЗУ:
  - Они сразу передаются процессору.
- Если данных нет:
  - Операционная система загружает страницу из файла подкачки.
  - Обновляет таблицы страниц.

## 6. Преимущества виртуальной памяти
1. **Изоляция процессов:**
   - Каждая программа имеет своё виртуальное адресное пространство.
2. **Эффективное использование памяти:**
   - В ОЗУ находятся только активные данные.
3. **Иллюзия большого объёма памяти:**
   - Программа может использовать больше памяти, чем доступно физически.

## 7. Итог
- Виртуальное адресное пространство создаёт абстракцию, которая:
  - Упрощает работу программ.
  - Позволяет работать с объёмами памяти, превышающими физические возможности системы.
  - Обеспечивает изоляцию и защиту процессов.

## ВЫДЕЛЕНИЕ И ЗАМЕЩЕНИЕ ВИРТУАЛЬНЫХ СТРАНИЦ

До тех пор, пока программа не обратилась к памяти, виртуальные страницы её процесса не проинициализированы. При первом обращении программы к очередной странице процессор приостанавливает работу программы и передаёт управление операционной системе. Последняя выделяет для виртуальной страницы физическую страницу в оперативной памяти и обновляет таблицу страниц. Если свободных физических страниц нет, то операционная система выгружает данные из некоторой занятой физической страницы в область подкачки на жестком диске и выделяет процессу освободившуюся страницу.

Для выбора выгружаемой страницы используются стратегии вытеснения, аналогичные стратегиям вытеснения для кэш-памяти. Вытесненная виртуальная страница помечается как выгруженная, и при последующем обращении к ней процессор также передаёт управление операционной системе, чтобы она могла вновь выделить для этой страницы физическую страницу. Такой порядок работы виртуальной памяти позволяет процессу использовать большое количество памяти, но реальную физическую память получать лишь по мере обращения к фрагментам этой памяти. При запуске процесс может запросить у операционной системы много памяти, но пока он не начал с ней работать, физическая память не будет расходоваться.

Читатель может легко убедиться в том, что современные операционные системы выделяют память описанным образом, написав следующую простую программу на C. Данная программа динамически, с помощью функции malloc, запрашивает большой объем памяти (например, 1 Gb), но обращается к этой памяти не сразу, а по прошествии некоторого времени. Если проследить за запущенной программой (в случае Windows для этого достаточно диспетчера процессов), то станет очевидно, что реальная физическая память выделяется не в момент вызова malloc, а по мере обращения к памяти из программы.
